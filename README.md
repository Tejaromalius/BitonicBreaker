# BitonicBreaker

A high-performance parallel and serial sorting library implementing various algorithms in C (Parallel) and C++ (Serial). This project was developed as part of a Parallel Computing assignment, focusing on optimizing sorting performance using MPI (Message Passing Interface) and OpenMP.

## Features

- **Parallel Implementations (C + MPI + OpenMP):**
  - **Bucket Sort (Hybrid):** A highly optimized hybrid algorithm combining parallel bucket sort with OpenMP-parallelized introsort.
  - **Sample Sort (Hybrid):** Combines sample sort distribution with k-way merging and OpenMP introsort.
  - **Bitonic Sort:** Efficient sorting network implementation.
  - **Merge Sort:** Parallel tree-structured reduction.
  - **Quick Sort:** Pivot-based parallel implementation.
  - **Bubble Sort & Selection Sort:** Baseline parallel implementations (Odd-Even Transposition and Local Sort + Serial Merge).

- **Serial Implementations (C++):**
  - Bubble Sort, Selection Sort, Quick Sort, Merge Sort, and Bitonic Sort.

- **Performance Focused:** Includes a benchmarking framework that generates detailed reports in the `reports/` directory, measuring execution time and validating correctness.

## Prerequisites

- **Parallel:** `mpicc` (OpenMPI or MPICH) and OpenMP.
- **Serial:** `g++` supporting C++14.
- **Build Tools:** `make`.

## Getting Started

### Building the Project

To compile both serial and parallel versions:

```bash
make
```

This will produce two executables: `sorting_serial` and `sorting_parallel`.

### Running Benchmarks

#### Serial Benchmarks

Run all serial algorithms:
```bash
./sorting_serial all
```

Run a specific algorithm (e.g., Quick Sort):
```bash
./sorting_serial quick
```

#### Parallel Benchmarks

Run all parallel algorithms with 8 processes:
```bash
mpirun -n 8 --oversubscribe ./sorting_parallel all
```

Run a specific algorithm (e.g., Bucket Sort):
```bash
mpirun -n 8 --oversubscribe ./sorting_parallel bucket
```

*Note: `--oversubscribe` is recommended if the number of MPI processes exceeds the available physical cores.*

## Performance Highlights

On a reference workload of $N = 1,000,000$ elements:
- The **Hybrid Bucket Sort** achieves significantly better performance than traditional parallel algorithms, being ~3.2× faster than Bitonic Sort and ~3.9× faster than Merge Sort on 8 processes.
- Detailed documentation on the hybrid algorithms can be found in `docs/bucket_sort.md` and `docs/sample_sort.md`.
